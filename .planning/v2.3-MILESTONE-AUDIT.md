### New Functional Gaps Found

#### INT-A1 — Tune Profile Key Collision (TUNE-01, OBB-03)

**File:** `src/yowo/engine.py:161`
**Code:** `model_name = f"{spec.family.value}{spec.size.value}"`
**Effect:** Profile key is `"yolo11n"` regardless of task. OBBEngine silently loads a detection-calibrated profile. Additionally, `tune_command` stores profiles under `"yolo11n-obb"` (raw CLI string) while `_load_tune_profile` uses `"yolo11n"` — these namespaces never meet.
**Consequence:** `yowo tune --model yolo11n-obb` saves a profile that OBBEngine can never load; OBBEngine always loads a detection profile instead.
**Severity:** Functional — silently applies wrong profile; user cannot tune OBB separately
**Fix:** `model_name = f"{spec.family.value}{spec.size.value}{'-' + spec.task if spec.task not in ('detect',) else ''}"`

#### INT-A2 — OBB Models Rejected by Benchmark Module (BENCH-01, OBB-01)

**File:** `src/yowo/benchmark/__init__.py:37`
**Code:** `_MODEL_PATTERN = re.compile(r"^(yolo(?:11|26))([nsmxl])(?:-(cls))?$")`
**Effect:** `yowo benchmark --model yolo11n-obb` raises `ValueError`. The `-obb` suffix is not recognized. OBB mAP/FPS cannot be measured.
**Severity:** Functional — OBB accuracy verification (mAP, FPS delta) not reachable
**Fix:** Extend pattern to `(?:-(cls|obb))?` and add OBB evaluation path
