  <action>
    1. Add `WarmupValidationError(BackendError)` to `src/yowo/errors.py`. Include it in `__all__`. Message format: "Warmup validation failed: {detail}. The model may be corrupt or incompatible with this backend."

    2. In `src/yowo/engine.py` BaseEngine:
       a. Add `import threading` and `self._infer_lock = threading.Lock()` in `__init__`.
       b. Add `_validate_warmup_output(self)` method that:
          - Creates a dummy PreprocessedTensor with zeros of shape (1, 3, H, W) using model meta input size
          - Calls `self._backend.infer(dummy_tensor)`
          - Validates output.ndim >= 2
          - Calls `self._validate_output_values(output)` (abstract method for subclass)
          - Raises WarmupValidationError with details on failure
       c. Call `_validate_warmup_output()` in `load()` after `self._backend.warmup()` but before `_finalize_load()` (in both the user-provided backend path and the fallback loop).
       d. Add abstract `_validate_output_values(self, output)` with default implementation that passes.
       e. In DetectionEngine, override `_validate_output_values()`: check that class score columns (output[:, 4:] or appropriate slice) are in [0, 1] range. Use a tolerance check: `np.any(output > 1.0 + 1e-3)` or `np.any(output < -1e-3)`.
       f. Wrap `_run_gpu()` body with `with self._infer_lock:`. The docstring already mentions callers should hold the lock -- now the lock is internal.

    3. In `src/yowo/classify_engine.py` ClassificationEngine:
       a. Override `_validate_output_values()`: check that softmax output sums to ~1.0 per sample (within tolerance 0.01) and all values in [0, 1].

    4. In `src/yowo/postprocess/_nms.py` `_class_aware_nms()`:
       a. Replace `return np.sort(np.asarray(indices, dtype=np.intp).ravel())` with deterministic sort:
       ```python
       kept = np.asarray(indices, dtype=np.intp).ravel()
       if len(kept) <= 1:
           return kept
       sort_key = np.lexsort((
           boxes_xyxy[kept, 0],    # tertiary: x1 ascending
           class_ids[kept],         # secondary: class_id ascending
           -scores[kept],           # primary: confidence descending
       ))
       return kept[sort_key]
       ```
       b. Update docstring: "Returns indices sorted by (confidence desc, class_id asc, x1 asc) for deterministic ordering."

    5. Write tests in `tests/unit/test_warmup_validation.py` using mock backends. Write tests in `tests/unit/test_thread_safety.py` using threading. Add `test_deterministic_ordering` and `test_deterministic_with_equal_scores` to existing `tests/unit/test_nms.py`.

    IMPORTANT: Use `threading.Lock` (not RLock) per user decision. The inference path is strictly linear, no reentrant risk.
  </action>
