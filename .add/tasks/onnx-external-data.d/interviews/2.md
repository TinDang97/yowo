## WHY THERE IS A SECOND INTERVIEW

Nothing was re-decided. The gate refused the PASS with `R:REQUEST` and
`R:SILENT` reported as having no passing check, which looked like two unbound
rejects and was not: the engine's rule grammar is `R:[A-Z0-9_]+`
(`.add/tooling/add.py:4097`), so `R:REQUEST-AS-FACT` parses as the id
`R:REQUEST` while the `covers:` token stayed the full hyphenated string, and
the two never matched. The ids are respelled `R:REQUEST_AS_FACT` and
`R:SILENT_DEGRADE`. The rule TEXT is byte-identical; only the identifier moved
into the alphabet the engine reads.

Three genuinely unbound rules were bound at the same time, by adding checks
rather than by accepting the gap: A6 (a pre-existing file in `output_dir` is
neither claimed nor touched) already had a test that no CHECKS line named;
A11 and A12 had none and now do.

Renaming an id changed the decision set, so the engine asked again. Every
answer is the same answer as interview 1, including the three that went to the
user and timed out -- those remain MINE, and interview 1 records what was
asked and what I took in the silence. Read that file, not this one, for the
three that matter.
