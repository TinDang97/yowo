# interview 1 — task-aware-weight-resolution

## A1 [who]
- asked: every existing caller — `engine.py:447`, `export/_exporter.py:94`, `benchmark/_runner.py:74`, and the ~60 tests that mock it — since M5 forbids a signature change and a task-blind caller must keep resolving detection
- if wrong: a caller that relied on always getting the detection weight breaks silently.
- answered: confirm

## A2 [which]
- asked: all three — `_REGISTRY`, `_CLS_REGISTRY`, `_OBB_REGISTRY` — because pinning ten of twenty-five is what produced a check that reads as complete and covers a tenth
- if wrong: effort is spent pinning assets nobody resolves.
- answered: confirm

## A3 [when]
- asked: `spec.task` at the top of `resolve_weights`, BEFORE the registry lookup, so one dispatch decides both the URL and the pin and they cannot disagree
- if wrong: and the task is consulted after the lookup, the pin and the URL can come from different entries, which is worse than today.
- answered: confirm

## A4 [absent]
- asked: `None` or missing as `detect`, matching `ModelSpec`'s own default, but an unrecognised STRING as an error naming what is registered
- if wrong: a typo'd task silently downloads a detection weight, which is exactly today's bug wearing a different hat.
- answered: confirm

## A5 [order]
- asked: `weights_path` first and unchanged — an explicit file is the user's own and no registry entry describes it
- if wrong: a user's fine-tuned checkpoint is compared against an official digest and every custom run refuses.
- answered: confirm

## A6 [experience]
- asked: someone who typed `--model yolo11n-cls` and got a detection weight — the message must name the task, the model, and the URL it went to, so the mismatch is visible rather than surfacing 200 lines later as a shape error in a conv layer
- if wrong: the next person debugs the architecture instead of the resolution.
- answered: confirm

## R:WRONGASSET [reject]
- asked: Returning a weight whose task differs from the spec's, on any branch.
- answered: confirm

## R:UNMEASURED [reject]
- asked: A digest recorded from anywhere but a download of that exact URL — copied from another variant, taken from a local file of unknown origin, or transcribed from a third party.
- answered: confirm

## R:COLLIDE [reject]
- asked: Two tasks resolving to one cache path.
- answered: confirm
