# interview 1 — real-backend-smoke

## A1 [who]
- asked: CI on every PR plus any contributor locally, because a smoke only one machine runs is the defect the integration conftest was written to fix
- if wrong: and it is CI-only, a contributor gets a slow local suite.
- answered: confirm

## A2 [which]
- asked: PYTORCH by explicit override, because it is the only one that loads a `.pt` and the box asks for "at least one"
- if wrong: and every backend is wanted, that is a wider box and a different node.
- answered: confirm

## A3 [which]
- asked: the existing `sample_image_path` fixture (bus.jpg), not a synthesised one, because a black frame measures 0 boxes and asserts nothing
- if wrong: and a committed fixture is wanted, the licence problem the conftest documents returns.
- answered: unanswered

## A4 [absent]
- asked: FAILURE — the image contains a bus and people, so zero boxes is a broken backend, not an empty scene
- if wrong: and the model legitimately finds nothing, the smoke is flaky. Measured today: 5 boxes, {bus, person}.
- answered: unanswered

## A5 [order]
- asked: NOT ASSERTED — NMS ordering is not this node's contract and pinning it would make the smoke brittle against a postprocess change
- if wrong: an ordering regression passes here and is caught by `m3`'s accuracy work.
- answered: unanswered

## A6 [experience]
- asked: someone who broke a backend and needs to know from the message which backend, which input and which invariant failed
- if wrong: so each assertion names them, rather than failing as a bare `assert len(boxes)`.
- answered: unanswered

## A25 [when]
- asked: EVERY PR, in the existing Weight Fixture job, blocking exactly as the unit gate does, because a smoke that runs after the merge tells you what you already shipped
- if wrong: and it is meant to be nightly, PR feedback slows by the job's runtime (40s today).
- answered: unanswered

## A7 [who]
- asked: the environment — `CI` set means fail, unset means skip — reusing `conftest._unavailable` rather than writing a second policy
- if wrong: two guards drift apart.
- answered: unanswered

## A8 [which]
- asked: all three the smoke depends on — the torch import, the weight and the image — because any one of them missing makes the run prove nothing
- if wrong: one uncovered absence is the hole the whole rule exists to close.
- answered: unanswered

## A9 [absent]
- asked: a message naming what was unavailable and why, because "skipped" alone is what let this rot
- if wrong: the message is noise.
- answered: unanswered

## A10 [when]
- asked: FIXTURE SETUP, so the failure is attributed to the missing input rather than surfacing as an unrelated error inside a test body
- if wrong: a reader debugs the wrong thing.
- answered: unanswered

## A12 [experience]
- asked: a contributor without network on a first clone — the difficulty is that a skip looks like a pass, so the message must say the run proved nothing
- if wrong: the wording is merely verbose.
- answered: unanswered

## A14 [which]
- asked: the OUTCOME — that the backend which ran is not the primary selection — rather than the log text, because a log line is not a contract and asserting on it would break on a reword
- if wrong: a silent change of *which* fallback is taken passes.
- answered: unanswered

## A15 [absent]
- asked: a check that asserts the fallback only where the primary is genuinely not the backend that ran, and skips with a reason otherwise
- if wrong: the check is red on a machine whose selector picks PyTorch first, which is a CI-host difference and not a defect. This is the one skip R:GREENSKIP permits, and R:GREENSKIP names it.
- answered: unanswered

## A16 [when]
- asked: "when a backend that loads a `.pt` is selected first, or the selector stops offering one that cannot" — either is a real change someone should see
- if wrong: the check is treated as a bug rather than a tripwire, so it says so in its own message.
- answered: unanswered

## A17 [order]
- asked: NOT PINNED — only that a fallback occurred and where it landed — because the chain is `degraded-mode-correctness`'s subject
- if wrong: a chain reorder passes here.
- answered: unanswered

## A18 [experience]
- asked: whoever changed the selector and saw it go red — the difficulty is concluding they broke something when they may have FIXED it
- if wrong: so the message must say the tripwire records today's behaviour and asks for a look, not a revert.
- answered: unanswered

## A19 [who]
- asked: the human maintainer, as with m1 box 6 and m2 boxes 1, 3 and 4
- if wrong: and process authority suffices, the cost is one interview round.
- answered: unanswered

## A20 [which]
- asked: the CLAIM — from "at least one real backend is constructed and executed" to what the smoke establishes — while KEEPING the purpose clause about the two tasks below, because that clause is why the box exists
- if wrong: the box loses the reason it was written.
- answered: unanswered

## A21 [when]
- asked: YES, in the AMENDED format m1 box 2 established
- if wrong: the milestone reads tidier and its history is gone.
- answered: unanswered

## A22 [absent]
- asked: NOT CLAIMED, named explicitly — ONNX, TensorRT, OpenVINO and CoreML are constructed by no unmocked check
- if wrong: a reader takes the box as a whole-matrix guarantee.
- answered: unanswered

## A24 [experience]
- asked: whoever picks up `degraded-mode-correctness` and asks what they can regress against — the difficulty is that "a real backend is executed" sounds like a working baseline when the execution asserted nothing
- if wrong: so the box must state what the smoke actually pins.
- answered: unanswered

## R:GREENSKIP [reject]
- asked: A CI leg that reports green while executing no backend. Scoped to the legs that MUST execute one — the smoke itself, its weight and its image. The fallback tripwire is not such a leg: it records a host-dependent fact, so where the primary backend already loads the weight it skips with a reason rather than failing for a difference that is not a defect (A15).
- answered: unanswered

## R:VACUOUS [reject]
- asked: An assertion a backend returning nothing would satisfy — a black frame, an `isinstance(..., list)`, a bare truthiness.
- answered: unanswered

## R:WIDEN [reject]
- asked: Claiming the smoke covers backends it does not execute.
- answered: unanswered

## R:SILENTREWRITE [reject]
- asked: Amending box 7 without recording that it was amended and why.
- answered: unanswered

## R:BEHAVIOUR [reject]
- asked: Changing selection or fallback behaviour under cover of a test-scoped node.
- answered: unanswered
