# interview 1 — artifact-cache-keys

## A1 [who]
- asked: the reader to be a single machine reusing its own artifacts across runs, not a shared or network cache, because every path here is under `~/.cache/yowo`
- if wrong: and the cache is shared between machines, the key needs a host identity too and collisions become cross-machine
- answered: confirm

## A2 [which]
- asked: them as the MINIMUM and the structure as open, because the box's own list omits the calibration set's CONTENT (it names the set, not its digest) and two files with the same directory name are not the same calibration · probe: changing an image inside the calibration directory must change the key · found: `cache_file = engine_path.with_suffix(".calib")` (`_exporter.py:508`) depends on the ENGINE path alone — not on the directory name and not on its contents, so even renaming the directory does not invalidate
- if wrong: and the directory name is the intended granularity, re-calibrating in place silently reuses
- answered: confirm

## A3 [which]
- asked: the three that exist — tune profile, INT8 calibration, TensorRT engine — and NOT the feature cache, whose shape clause the box names separately and which `feature-cache-honesty` closed on 2026-09-16
- if wrong: the feature cache is re-litigated and the box's last sentence is done twice
- answered: confirm

## A4 [when]
- asked: it that absence is decided at key-construction time on the live machine and recorded in the key as an explicit absent marker, not as an empty string, because an empty string is indistinguishable from a probe that returned nothing · probe: a key built with a missing driver version must differ from one built with a driver version of ""
- if wrong: two genuinely different machines share a key
- answered: confirm

## A5 [absent]
- asked: "absent" to be a VALUE that participates in the key rather than a wildcard that matches anything, so an artifact built where the driver was unknown is not reused where it is known
- if wrong: the conservative reading costs a cache miss on machines that cannot probe
- answered: confirm

## A6 [absent]
- asked: covers: S2 · the box does not say what to do with cache entries already on disk; I assumed they were unreachable and would need re-tuning · probe: an existing profile written under the old scheme must not be loaded as if it matched · found: OVERTURNED — a profile is SELF-DESCRIBING. It stores its own `fingerprint`, and `load_profile` already compares it and returns None with a re-tune warning on a mismatch (`_profile.py:197`). `backend` and `precision` are stored the same way and simply never compared. So the fix is a stricter comparison against data already on disk, no profile is orphaned, and nobody re-runs a sweep they did not have to -> the reading I took was needlessly destructive; taking the non-destructive one
- if wrong: the reading I took was needlessly destructive; taking the non-destructive one
- answered: correct

## A7 [order]
- asked: the key to be order-INDEPENDENT of how the structure is declared but stable across runs, by rendering fields in a canonical sorted order, so reordering the dataclass does not invalidate every cache on disk
- if wrong: and order should matter, every field reorder is a silent cache flush
- answered: confirm

## A8 [experience]
- asked: the harmed party to be someone whose benchmark or deployment silently used an artifact built for other inputs, so a key MISS must be cheap and silent while a key that cannot be built at all must be loud
- if wrong: every cache miss logs a warning and the logs become noise
- answered: confirm

## A9 [when]
- asked: it as computed BEFORE the artifact is produced, so the path it writes to is already the keyed one and no rename is needed
- if wrong: an artifact is written then moved and a crash between the two leaves an unkeyed file
- answered: confirm

## A11 [who]
- asked: the writer to be this package in every case — the tune sweep, the INT8 export and the TensorRT EP under our provider options — and NOT a user hand-placing files, so we may choose all three key schemes without a compatibility contract · probe: no public API accepts a cache path from the caller · found: WRONG — both `save_profile(profile, path=None)` and `load_profile(model, hw, path=None)` take a caller path and both are exported from `yowo.tune`. The escape hatch already exists, which cuts the other way than I feared: changing the DEFAULT scheme takes nothing away from a caller who names their own path
- if wrong: so the scheme may be ours, and the override stays public
- answered: correct

## A10 [order]
- asked: last-writer-wins as acceptable because both wrote the same invalidation set and therefore the same artifact, which is exactly what the key asserts
- if wrong: and artifacts are not deterministic, the key is claiming more than it can
- answered: confirm
