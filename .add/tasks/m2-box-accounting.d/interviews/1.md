# interview 1 — m2-box-accounting

## A1 [who]
- asked: the human maintainer, as with m1 box 6 and m1 box 2 before it
- if wrong: and process authority suffices, the cost is one interview round.
- answered: confirm

## A2 [which]
- asked: ONLY the `cap.read()` clause, since `.get()` and `.join()` are satisfiable and satisfied
- if wrong: two true clauses are removed with the false one.
- answered: confirm

## A3 [when]
- asked: YES, in box 2's AMENDED format, because an undated rewrite is indistinguishable from the box always having said that
- if wrong: the milestone reads tidier and its history is gone.
- answered: confirm

## A4 [absent]
- asked: NOT CLAIMED — the properties are FFMPEG-only and a file or webcam capture does not honour them
- if wrong: the box implies a guarantee for sources that cannot have it.
- answered: confirm

## A6 [experience]
- asked: someone auditing whether yowo can hang — the difficulty is that "a gate on bare `cap.read()`" sounds satisfied by the four bare `cap.read()` calls still in the file, which are fine because the CAPTURE is bounded
- if wrong: so the box must say construction, or a reader greps, finds them, and concludes the box is broken.
- answered: confirm

## A7 [which]
- asked: DROP, with the reason recorded, because the cycle check mocks `cv2.VideoCapture` and a descriptor count against mocks cannot fail
- if wrong: and fds must be counted, that needs a real-capture fixture and belongs with `real-backend-smoke`, which is the node that introduces real resources.
- answered: confirm

## A8 [when]
- asked: "when a check drives a real capture", and naming that rather than deleting the concern
- if wrong: the concern is lost and nobody counts descriptors ever.
- answered: confirm

## A9 [absent]
- asked: "the same count as before the cycles", which is trivially true under mocks and is exactly why the clause is being dropped rather than kept and satisfied
- if wrong: a vacuous pass is considered evidence.
- answered: confirm

## A11 [experience]
- asked: an operator deciding whether a long-lived process leaks — the difficulty is that "fd" in the box implies someone checked, and nobody did
- if wrong: so its absence must be visible in the box, not only in a task receipt.
- answered: confirm

## A13 [which]
- asked: the SYMBOL — `RTSPStreamSource.reconnect` — with the line as a hint, because a symbol survives edits and a line number does not, which is the defect being fixed
- if wrong: precision is lost; the symbol is unambiguous in this file.
- answered: confirm

## A14 [when]
- asked: YES, both arms recorded, with the arm taken named — the rebind is observed — so a later reader sees the choice rather than assuming there was none
- if wrong: the box reads as though only one design was ever possible.
- answered: confirm

## A15 [absent]
- asked: KEEP, because it is the box's most useful sentence and it is still true
- if wrong: a future node replaces the identity checks with a tally and the defect returns silently.
- answered: confirm

## A17 [experience]
- asked: a reviewer verifying the box is real — the difficulty is that a stale line lands them in unrelated code and they conclude the box is confused rather than that the file moved
- if wrong: so the citation must be one that survives an edit.
- answered: confirm

## R:SILENTREWRITE [reject]

- answered: confirm

## R:WIDEN [reject]
