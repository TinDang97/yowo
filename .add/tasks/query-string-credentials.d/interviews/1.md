# interview 1 — query-string-credentials

## A1 [who]
- asked: an operator's signed camera URL — HLS `?token=`, `?auth=`, CDN `?st=`/`?e=` — which is the normal way a large share of cameras authenticate, not an exotic case
- if wrong: and only userinfo is ever used here, this node costs a digest suffix on ids that have no query at all, which is nothing, since M6 leaves those byte-identical.
- answered: confirm

## A2 [which]
- asked: that verbatim
- if wrong: ids carrying a query grow a suffix.
- answered: confirm

## A3 [when]
- asked: BEFORE redaction, over the original query and fragment, since a digest of the redacted form is identical for every URL and preserves no identity at all
- if wrong: every query-bearing camera collapses to one id, which is R:COLLAPSE.
- answered: confirm

## A4 [absent]
- asked: byte-identical return with NO digest appended, so nothing that works today changes shape
- if wrong: every existing `source_id` for a file, a directory or a webcam changes, breaking anything keyed on it.
- answered: confirm

## A5 [order]
- asked: original order preserved, because reordering merges `?a=1&b=2` with `?b=2&a=1` and the whole point of M2 is that distinct inputs stay distinct
- if wrong: two orderings of one query collapse.
- answered: confirm

## A6 [experience]
- asked: an operator reading a log line who must be able to tell WHICH camera failed and see that redaction happened, hence keys kept, values emptied, and a visible digest marker rather than a silently truncated URL
- if wrong: a redacted id is indistinguishable from a camera that genuinely had empty parameters.
- answered: confirm

## A7 [absent]
- asked: honest documentation — a short digest over a LOW-ENTROPY query such as `?channel=2` is effectively an encoding of it, and that is acceptable because a channel number is not a secret, while a high-entropy token is not recoverable from it
- if wrong: someone reads the digest as a security control rather than an identity control.
- answered: confirm

## R:DENYLIST [reject]
- asked: Deciding what to redact from a query by matching key names.
- answered: confirm

## R:COLLAPSE [reject]
- asked: Any change that makes two distinct camera URLs produce one identifier.
- answered: confirm

## R:BYTEDRIFT [reject]
- asked: A URL with nothing to redact coming back other than byte-identical.
- answered: confirm

## R:REVERSIBLE [reject]
- asked: A digest, encoding or marker from which the original secret can be recovered.
- answered: confirm

## R:TICKBOX [reject]
- asked: Ticking m1 box 6 before the four sinks are green against this credential form.
- answered: confirm
